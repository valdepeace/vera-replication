# VERA-01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir un harness modular en Python que replique la comparación generate–validate–repair de la tesis (`MAX_REPAIRS` 0 frente a 3) en Java, Python y Node con auditoría de los éxitos, y ejecutarlo en este equipo con los cuatro modelos de la tesis y una extensión con modelos actuales.

**Architecture:** Un paquete `vera` con un núcleo (tipos, almacén de trazas, parser, motores de inferencia, flujo de tres nodos generar→validar→reparar), adaptadores por lenguaje (validación y auditoría) y un módulo de análisis. El "método" (el flujo) es una pieza intercambiable pa que VERA-03 enchufe otros. Cada ejecución queda en un JSON atómico, lo que permite reanudar y reanalizar sin invocar modelos.

**Tech Stack:** Python 3.12.10 (`pytest` 9.1.1 ya instalado), librería estándar pa HTTP y subprocesos, `pandas` 3.0.3 ya instalado, `statsmodels` y `scipy` (a instalar en un `.venv` del proyecto) pa el análisis. Ollama 0.40.13, llama-server (extensión), JDK Temurin 11.0.23, Maven (a instalar), Node 24.8.0.

**Spec:** `docs/superpowers/specs/2026-11-22-vera-01-design.md` (los ejecutores leen ambos).

## Global Constraints

- `num_ctx` = 8192, `keep_alive` = `"30m"`, `num_predict` = 2048 por llamada; lo truncado cuenta como fallo y **consume una reparación**.
- Condiciones: `MAX_REPAIRS` 0 (baseline) y 3 (reparación); mismo prompt, parser, modelo y comando de validación en ambas.
- Bloque determinista: modelos `llama3.1:8b` y `qwen2.5-coder:7b`, 10 métodos de `StringUtils`, temperatura 0, semilla fija, **cada ejecución repetida una vez** pa medir estabilidad. Bloque estadístico: los 4 modelos (`llama3.1:8b`, `qwen2.5-coder:7b`, `qwen3:8b`, `gemma4:e4b`), 20 métodos, temperatura 0,7, 15 repeticiones por método y condición (2.400 ejecuciones), ejecuciones independientes con semilla registrada.
- Proyecto Java: Apache Commons Lang, commit `89bb30909bf873d75f5e06d144f9b2e72d74c076`; validación con Maven en modo desconectado, limitada al test generado, JUnit 5. La suite completa no entra en el veredicto.
- Servidores Ollama: 11434 (modelos en `G:`) y 11435 (modelos en `E:\ollama-vera\models`). **No** cambiar la variable global `OLLAMA_MODELS`, **no** tocar los modelos preexistentes de `G:` (3,7 GB libres) y **no** copiar ni duplicar modelos.
- Todo lo nuevo en disco va a `E:\vera-data` (Maven, repositorio local de Maven, checkouts) o al repositorio, inventariado en `docs/ollama-vera-models.md`; sin tocar el `PATH` global.
- Fallos de infraestructura (tiempo agotado de Maven, carga del modelo, falta de memoria, servidor caído): se reintentan 2 veces; si persisten, la ejecución queda `valid=False` y fuera de las métricas. Nunca cuentan como fallo del modelo. Las corridas parciales, las interrumpidas y el piloto del 21 de noviembre no entran en ninguna métrica.
- Auditoría: cinco resultados excluyentes `EMPTY`, `TEST_FREE`, `ASSERTION_FREE`, `NO_FOCAL`, `REAL`; solo `REAL` cuenta como éxito sustantivo.
- Criterio de "mejora": diferencia de tasas `REAL` positiva con intervalo de confianza del 95 % que excluye el cero (contraste de dos proporciones independientes).
- La extensión (VERA-01b) no se mezcla con las estadísticas de la réplica y se informa aparte, con el motor declarado.
- Convenciones del usuario: los mensajes de commit van en español de registro fino y terminan con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; solo se hace commit si el usuario lo autoriza. **El proyecto aún no es un repositorio git**: la Tarea 1 empieza pidiendo permiso pa `git init`.
- Antes de borrar nada o de lanzar el bloque estadístico, confirmación expresa del usuario.

## Review Focus

1. Un JSON válido con `code` vacío, nulo o solo espacios debe contar como fallo de parseo (`empty_code`), nunca como un test aceptado ni como excepción (Tarea 2).
2. Una salida enorme de Maven no debe desbordar el contexto de 8192 en la reparación: el diagnóstico se recorta a 4000 caracteres (Tarea 4).
3. Maven con salida 0 y "No tests were executed" (test sin `@Test`) es un "pasa" del runner que la auditoría debe clasificar como `TEST_FREE`, sin romper nada (Tareas 5 y 7).
4. Un corte a mitad de una ejecución (apagón, Ctrl+C) no debe dejar un registro a medias que se cuente ni que impida reanudar (Tareas 1 y 9).
5. El test generado nunca debe quedar en el checkout de Commons Lang, ni tras un tiempo agotado ni tras una excepción (Tarea 7).
